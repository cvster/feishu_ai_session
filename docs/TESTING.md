# 测试

常规检查：`pnpm test`、`pnpm typecheck`、`pnpm build`。真实飞书集成测试默认关闭，不会随常规测试发送消息或创建群。

## 真实 worker / 原生工具 / 飞书验证

```bash
BRIDGE_LIVE_SMOKE=1 \
BRIDGE_LIVE_PROFILE=lennox-codex \
BRIDGE_LIVE_TOOLS=codex,zcode,kilo \
BRIDGE_LIVE_WORKSPACE=/home/pc/code/pc_localtask \
pnpm test:live:bridge
```

当前原生测试驱动支持 Codex、ZCode、Kilo。其他 worker 尚未纳入本轮真实验证。测试使用 `workers/*/endpoint.json` 自动发现部署中的 worker，读取其能力声明，并通过统一 worker 接口检查会话和消息。真实输入、创建和改名通过各工具自己的原生接口完成；ZCode 原生输入使用官方远控 V4 的 `sendText`，由原生工具记录 `mobile` 来源。飞书输入和群改名使用群主的用户身份。

运行条件：桥接服务和目标 worker 在线；各工具已登录且模型有额度；ZCode 桌面已打开指定项目并配置远控链接；群主的 `lark-cli --profile <机器人 app ID> --as user` 授权包含发消息、读群消息、更新群和个人群免打扰权限。测试不会自行登录或替换账号。

每个工具复用活跃的 `AA-飞书桥接-autotest` 会话；不存在时才创建。新会话在 `BRIDGE_LIVE_WORKSPACE` 项目路径下创建。已存在会话若路径不同、身份不明确或记录的 ID 失效，测试报错，不另建同名会话。消息往返后再次检查原生目录，避免桥接旧目录把会话移回其他项目。创建返回的原生 ID 在后续改名之前保存，便于部分失败后定位和清理。已成功清理的上轮会话不再复用，下次运行可创建新的活跃测试会话；未经测试记录确认的归档会话不会被自动替换。

验证步骤：等待生产桥接自动建群及一对一绑定；设置并查询群主的免打扰状态；群消息进入原生会话，模型回复返回飞书；原生输入及回复同步到飞书，且输入具有原生来源；会话改名同步到群，群改名同步到会话。消息阶段失败后仍继续独立的改名检查，整体结果仍为失败。无论通过还是失败，结束时都尝试归档测试原生会话并解散测试群，并查询确认结果。先归档以防自动建群扫描重新创建群；一个清理操作失败时仍尝试另一项，整体测试判失败。群已被重新绑定时拒绝解散，避免影响其他会话。

归档通过各工具的原生接口完成，ZCode 使用桌面远控的原生归档接口，并查询桌面 task index 的归档列表验证（运行时 `session.archivedAt` 不随桌面归档变化）；不将桥接目录中的“已归档”状态当作原生归档成功。清理进度逐项持久化，清理不完整时，下次运行先重试尚未完成的操作，完成前不创建新的测试会话。测试进程被强制终止时无法执行 `finally`，保留的 ID 会供后续恢复使用。

解散群使用已登录的群主用户身份，需要用户授权 `im:chat:delete`（或 `im:chat`），不要求机器人额外拥有删除群权限。缺少授权时，报告记录缺失权限，保留待清理记录；授权后下次运行会先重试清理。

`BRIDGE_LIVE_HOME` 可指定状态根目录，默认 `~/.lark-channel`。测试加载目标 profile 的 `runtime.env`。持久记录和报告位于 `<profile>/autotest/`：`sessions.json` 保存原生 ID、项目路径、群 ID 和清理进度；`reports/*.json` 保存阶段、结果、清理状态和失败原因。报告不包含聊天正文或凭据。全套真实测试持有排他锁，避免并发运行创建重复会话或交叉改名。
