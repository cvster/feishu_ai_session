# 个人 AI 会话群网页

已实现轻量网页：工具 → 项目 → 会话三级侧边栏，只展示绑定个人 AI 会话群的活跃会话。支持搜索、聊天、实时回复、双向名称同步和手机布局。工具名称取自 worker manifest，不在页面维护工具列表。

## 启用

在完成桥接版本部署后，为对应 profile 配置网页：

```bash
lark-channel-bridge web configure --profile <profile>
# 从源码运行时：node dist/cli.js web configure --profile <profile>
lark-channel-bridge web status --profile <profile>
```

默认地址 `http://127.0.0.1:3345`，本机回环访问免登录，页面直接进入会话且不显示退出按钮。configure 只显示一次随机登录 Token，磁盘仅保存其 SHA-256 摘要；也可配置固定密码，磁盘保存带随机盐的 scrypt 哈希。随后启动或重启**桥接服务**即可访问，无需单独运行前端服务；configure 本身不重启服务。已有 worker 不随桥接重启。

可用 `--host <本机IPv4> --port <端口>` 指定监听地址；`--host 0.0.0.0` 监听所有 IPv4 网口，`--host ::` 同时监听所有 IPv4/IPv6 网口。通配监听的 Host 校验使用连接实际到达的本机 IP，回环入口也接受 localhost；不接受任意域名 Host。

支持通过 `--also-host <本机IPv4...>` 同时监听多个网卡，通过 `--trusted-network <IPv4 CIDR...>` 配置免登录来源。例如本机与 `192.168.188.0/24` 网段免登录：

```bash
lark-channel-bridge web configure --profile <profile> --host 127.0.0.1 --also-host 192.168.188.1 --trusted-network 192.168.188.0/24
# 所有网口使用 36666，本机与指定网段免登录，其他来源用固定密码或 Token：
read -rs -p '固定密码: ' BRIDGE_WEB_PASSWORD
export BRIDGE_WEB_PASSWORD
lark-channel-bridge web configure --profile <profile> --host :: --port 36666 --trusted-network 192.168.188.0/24 --password-env BRIDGE_WEB_PASSWORD
unset BRIDGE_WEB_PASSWORD
```

免登录判断使用 TCP 连接的真实来源地址，不信任 `X-Forwarded-For` 等代理头。通配监听不会扩大免登录网段，本机回环保留免登录，`::` 的 IPv6 回环也免登录。其他来源在登录框输入固定密码或登录 Token；程序也可通过 `Authorization: Bearer <网页登录 Token>` 访问 HTTP/SSE API。写请求仍须发送与访问地址一致的 Origin。免登录请求同样接受 Host、同源和所有者校验。配置中的 `additionalHosts` 和 `trustedNetworks` 可选，旧配置保持原有行为；通配监听不与额外监听地址组合，变更监听地址或免登录网段立即撤销现有访问，重启桥接后生效。

非回环入口的登录 cookie 为 HttpOnly、SameSite=Strict，12 小时过期。登录状态保存在 profile 下的 `web-sessions.json`（权限 600，仅保存随机 cookie 的 SHA-256 摘要），正常部署和桥接重启后继续有效；密码、登录 Token 配置也保留。退出登录立即删除持久记录，重启不恢复已退出的登录。登录会话绑定 profile、配置摘要及当前机器人所有者；更换密码或 Token、禁用入口或所有者变化会撤销旧登录。Token 验证实时读取配置，轮换后旧 Bearer 请求和 SSE 也失效。配置文件在 `profiles/<profile>/web.json`，权限 600。

```bash
lark-channel-bridge web disable --profile <profile>
```

禁用立即拒绝 API 并关闭 SSE；服务下次重启后不再监听。改变监听地址需重启桥接。不要将 worker token 或飞书应用凭据填入网页登录框。

## 通信与边界

```text
网页 ── HTTP / SSE ── 桥接服务 ── 统一 worker HTTP ── 原生工具
                         │
                         └── 飞书消息、群名同步
```

- `apps/bridge-web/page.ts`：无构建依赖的原生 DOM 页面，随 CLI 打包，不执行工具命令。答案以安全文本和代码块展示，不执行消息里的 HTML；保留思考状态和工具调用数量、状态的纯文字摘要，不展示思考或工具详情，也不提供展开入口。
- `src/web/server.ts`：按真实连接来源判断免登录，其他来源使用密码/Token 登录 cookie 或 Bearer Token，包含 Host/Origin 检查、JSON 请求限制、登录限流和 SSE。多个浏览器共享按会话的观察结果，慢连接会断开并重新读取快照。
- `src/web/service.ts`：统一 `list/read/send/rename/control/favorite`，依据绑定、账户和 worker capabilities 授权。会话身份包含 profile、应用、群、工具、sourceId 和 nativeId，页面持有其摘要。归档/共享/辅助/话题群被排除，已失效群沿用现有群清理流程。读取失败不会被当成归档。
- `src/bot/intake-queue.ts`：飞书和 Web 共用持久化收件箱、去重和 PendingQueue。执行、会话锁、回复卡片、完成时艾特所有者沿用原桥接路径。网页文本中的 `/exit` 等仅作为模型输入。
- worker：读取原生记录、处理执行及工具协议。Claude 和 Dsh 补充了 conversation；Kilo 补充原生轮次与 job 的关联，Zcode 通过已使用的原生输入元数据关联 job。桥接仅接受可由 worker journal 验证的 job 关联。

侧边栏每个会话右侧提供“⋯”菜单，可修改会话名、归档和复制，无需切换当前对话。操作与确认按钮绑定点选的会话，切换会话时忽略迟到结果。输入框上方提供停止、刷新、复制、归档和设置五个仅图标按钮，复用飞书卡片的原始 PNG（停止完成态使用同形状灰色图标）；点击设置打开模型与推理程度配置表单，保存及刷新模型复用飞书配置命令。切换会话不自动读取模型选项。右侧发送按钮加高并居中对齐。手机回车换行，桌面 Enter 发送、Shift+Enter 换行。`src/web/controls.ts` 将现有命令卡片转换为网页表单和按钮，复用相同命令处理器；复制选项和归档确认均在网页完成。后续按钮使用服务端签发、绑定当前会话及所有者的 15 分钟令牌，仅允许已展示的命令和表单选项；提交重试复用结果。打开归档确认不查询 worker 的模型、能力或会话选项，固定展示两个红色按钮；点击确认后才重新校验会话与权限：归档保留群和历史，归档并解散群先归档再解散群、清理关联，保留原生会话历史。飞书卡片仍采用快速返回、异步更新的回调流程。

新增 Web/UI/服务没有按 Codex、Claude、Zcode、Kilo、Dsh 分支。操作由 `conversation`、`sessions.rename`、`nativeSessionNames`、`jobs.submit` 决定。新增 worker 实现统一协议和能力声明后无需修改网页。桥接既有历史工具兼容代码仍存在，例如 Codex 名称账本旧键。

## 消息与状态

网页先以机器人消息在个人群发送“来自网页”，再将同一消息 ID 放入正常持久队列。HTTP 202 表示排队，页面随后区分工具接收、执行、完成、失败及状态待确认；问答待处理时提示前往群或原工具。

点击发送立即清空输入框，在对话底部显示本地消息气泡及“发送中”；HTTP 202 后仅在输入框上方的排队区显示，工具接收后再进入消息记录。后续持久回执或实时快照确认同一请求后自动清除发送未确认提示。
服务端给桥接轮次附带当前所有者的网页 `requestIds`，客户端按请求身份替换本地气泡，支持同文重复发送及多条输入合并为一个任务，不按文本猜测匹配。
发送未确认时保留消息和请求 ID，标注“发送未确认”，点击重试复用原请求；刷新也能恢复待重试消息。
实时确认早于 HTTP 响应时不会重复插入或退回失败状态。切换会话、历史加载、归档和登录变化沿用会话身份及响应顺序校验。

请求 ID 在浏览器本地保存到确认排队，重试复用原 ID；服务端账本只保存请求指纹、身份和群消息回执，完整消息使用现有 inbox。群投递使用稳定 UUID；未知结果超过 55 分钟暂停自动重发。若群发送后绑定变化，拒绝后续执行，已发送的群消息保留供检查。

聊天读取统一 native conversation 和 worker job 游标；桥接输入使用 inbox 中的原消息，不展示执行 prompt 的策略/上下文。可关联的原生轮次按 job ID 去重。历史中无法确认来源的桥接输入不展示，其较早的回答可展示；来源不明确的输入不会被回推到飞书。Claude SDK 来源按不确定来源处理，已确认 CLI/VS Code 输入可回推；Dsh 使用原生 source 元数据区分已标记的桥接输入。

SSE 每秒共享读取订阅中的会话；完成的 job 复用缓存和事件游标，不重复扫描完整事件。断线后重新获取权威快照，断开网页或桥接观察不取消 worker 任务。worker 离线时保留绑定项、禁止发送；运行中已有历史在内存缓存保留，桥接重启且 worker 离线时需等待恢复才能读取原生历史。

网页在当前标签页内存中缓存最近 20 个已加载会话的内容和滚动位置。切换回来立即显示缓存，由 SSE 获取最新内容；首次打开才请求历史。切换和更新使用即时滚动，阅读历史时保留当前位置，接近底部时跟随新回复。过期请求不会覆盖新会话或较新的实时快照；绑定失效、登录身份变化时清理缓存，刷新网页后重新加载内容，并优先恢复上次选中的有效会话；没有有效选择时才打开最近更新的首个会话。选中会话同时更新当前 URL 的 session 参数和浏览器本地记录，避免旧链接使刷新回到之前的会话。

回复支持 Markdown 表格、标题、列表、任务列表、引用、粗体、删除线、代码块和链接，普通网址也可点击。宽表格在自身区域横向滚动。服务端使用 Marked 解析，仅向网页提供允许的展示节点；浏览器通过 DOM 文本构建内容，不插入原始 HTML。链接仅支持 HTTP、HTTPS、mailto，图片显示为链接，原始 HTML 和不支持的地址保持文字。解析结果有容量受限的缓存，流式未完成的 Markdown 仍可阅读。

`answerSections` 保留统一 worker 快照中可见文本块的边界，各段用留白和分隔线区分，最后回复不会与前面输出紧贴。保留原 `answer` 字段作为兼容纯文本。若 worker 只提供单个文本块，不通过关键词猜测“最终总结”；该块内继续按 Markdown 段落排版。思考和工具细节不进入展示节点，仅保留原有状态摘要，无工具特化处理，也无需更新 worker。

## 名称

网页改名与现有名称观察串行执行，同步原生会话和个人群并保存基线。原生改名成功、群改名失败时，后续扫描会重试群改名；两端成功后忽略旧快照回声。群/工具端改名继续使用 15 秒轮询，随后更新网页；同时修改沿用群名优先规则。

## 验证

`tests/integration/web/personal-web.test.ts` 使用真实本地 worker HTTP、持久 inbox、公共队列、群投递替身和 HTTP/SSE；覆盖五个 worker 的网页停止、设置保存/预览、复制选项和归档确认，及 Codex、Zcode、Kilo 的三端消息、三处名称、并发去重、重启恢复、绑定失效、离线、本机免登录、非回环认证、同源/Host 校验、入口禁用、令牌重试及跨会话拒绝。Claude/Dsh 记录适配另有解析测试，Dsh 有原生协议进程夹具测试。浏览器验证登录、发送/回复、改名、会话切换、HTML 文本安全以及手机布局。

这些是隔离集成/浏览器验证。真实飞书群及真实模型的 Web autotest 尚未执行；按项目交付流程部署桥接和网页，已有 worker 保持运行。旧 worker 未提供新能力时，页面会保留桥接聊天并提示原生对话读取不可用。

侧边栏名称每 15 秒读取真实个人群名，独立于 worker 改名能力和旧绑定名称；飞书查询短暂失败时保留最近确认的群名，并将写入入口标为不可用。名称同步的正常检查也会回填旧绑定名称，即使原生会话和群已经同名。

侧边栏开头固定提供“收藏 → 会话”，会话名称后附项目名，不再增加项目层；原工具列表仍保留会话。
每行的工具图标直接复用飞书群头像的 PNG，星标使用饱满的五角星，收藏后亮起。收藏按钮不切换或加载对话。
`POST /api/sessions/:id/favorite` 显式设置布尔 `favorite`，重复设置幂等。收藏保存在桥接端
`web-receipts.json`，按所有者和稳定会话身份隔离，刷新、重启和不同网页入口共用，SSE 同步状态。
旧账本没有 `favorites` 字段时兼容读取；归档或失效绑定的收藏不再显示，不影响原历史。

默认在收藏下方显示“最近更新 → 会话”，会话名称后附项目名，收录全部可见个人会话中最近更新的 9 个，包含收藏会话。
按统一 worker 的 `updatedAtMs` 排序，桥接新输入也计入更新时间，原生列表刷新后通过 SSE 同步。
不会把目录扫描时间作为原生会话活动时间。搜索只过滤已入选的最近会话，不把旧会话补进列表。
最近更新的会话菜单提供“移出最近更新”，只移出当前浏览器的最近列表，收藏、原工具列表和会话内容不变；刷新及重新部署后仍移出，有新活动时自动重新入选。移出后按原排序补齐下一项。
侧边栏底部“设置”可关闭最近列表，或将数量设为 1–50；设置保存在当前浏览器、当前网页地址的本地存储。
桌面侧边栏默认宽度 325px，可拖动右边缘或用方向键调整；宽度记在同一份本地设置中，双击边缘恢复默认。
窄屏自动限制宽度，手机展开式侧边栏占屏幕宽度的 90%，右侧保留遮罩区用于关闭。

## 桥接控制台

侧边栏底部的“控制台”打开 `/console`，与聊天网页共用桥接进程、登录 cookie、密码/Token、可信网段、所有者校验和同源规则。已有网页登录可以直接复用，无需启动额外服务或更新 worker。

- **运行概览**：桥接连接、在线 worker、未发送消息、待完成任务、异常任务和关联异常。工具与能力来自发现结果和统一 worker API，离线时保留关联。
- **消息队列**：展示持久 inbox 原消息、发送人、等待时间、拒绝/暂缓原因与 worker 回执状态。详情包括原消息和已取得的状态事件，不展示执行 prompt、思考或工具详情。
- **AI会话群管理**：只显示个人 AI 会话群及其最后一条会话关系，分别读取群是否解散、原生会话是否归档。会话已归档而群保留时提供“解散群”；群已解散而会话保留时提供“归档会话”；两边均正常时不提供管理按钮，两边均关闭的记录不再显示。群解散后的最后关系独立保存，不随路由历史 GC 删除。会话状态与检查结果分开：会话状态为正常、已归档、不存在、未创建或工具不支持；检查结果为成功、Worker 离线、读取失败或尚未检查。读取失败保留上次确认的状态与时间，没有历史证据时显示尚未检查，不推断归档或解散。确认状态写入本 profile 的 `web-management-state.json`，按机器人、数据源和原生会话身份隔离，重启后仍保留；仅 worker 明确返回不存在或不支持时记录对应状态。当前检查失败不提供关闭操作，执行前重新校验关系与所有者，并使用既有解散清理路径和统一 Worker 归档接口。
- **共享群管理**：列表采用会话 → 群两级展示，同一原生会话的共享群与私聊群合并到一个可展开会话项，未绑定的群显示在“待关联”项。按工具、Worker 来源及原生会话 ID 分组，同名会话互不混合；自动刷新保留展开状态，每个群仍单独管理。选择或修改共享会话采用工具 → 项目 → 会话三级联动选项，项目以完整路径区分。包括没有绑定的待关联群、已启用共享群、私聊群、退出中及已关闭入口。显示实际群名、共享会话、工具、项目和关联异常，可筛选状态、搜索，并打开绑定的个人原会话。

每 10 秒自动刷新，服务端合并并发查询并短暂缓存。队列最多展示 300 条，待处理优先；不是原生工具任务的完整历史。

“重新发现 Worker”和“同步名称”调用既有发现及名称扫描路径。“重试”只释放尚未提交、未进入处理队列的 inbox 消息退避，并让正常调度器继续处理；操作前重新核对 worker 持久回执。已接收、已完成、结果未知或无法读取 worker 回执的消息不可重发。这些维护操作不新增提交通道，也不重启服务、清空队列或改变权限。

共享群管理可为待关联群选择会话，或将已启用的群切换到其他工具的已有会话。选择列表来自统一 worker 会话接口，只包含可共享的未归档会话，可按工具、会话名或项目路径搜索。复用飞书所有者选会话的绑定流程，并再次核验所有者、群状态、worker 身份和会话状态；本群存在未提交消息、worker 当前未完成任务或无法读取任务状态时拒绝切换。活动任务沿用协议的 accepted/running 定义；已结束但结果未确认的 unknown 和缺少旧任务记录的历史回执继续保留诊断，切换不会重发旧消息。每个群仅首次成功绑定时发送启用通知，后续换会话、重复选择及退出后重新绑定均不再向群或所有者发送绑定通知；首次绑定状态持久化，旧的已绑定记录按已通知迁移。切换会使旧操作和旧审核授权失效，保留原会话、其他共享群及已经创建的私聊群。私聊群保持创建时的关联，可在列表单独退出。

“机器人退出群”提供红色确认按钮，复用既有退群流程：关闭本群入口、取消本群未发送消息、停止本群任务，再以应用身份移除机器人。群本身、原会话及其他共享入口保留；失败显示“退出中”，可以重试。选会话与退出操作按群串行，旧页面携带的关联身份不能误操作已经切换的群。更改路由先持久化为未启用状态，写入中断后留在待关联状态，避免半写入的关联接收新消息。

网页设置可选择收藏与最近更新是否默认展开，以及收藏在前或最近更新在前。默认两项展开、收藏在前；偏好保存在浏览器本地，手动展开/收起在当前页面更新时保留。
