# 辅助群：私聊关联已有会话与简化权限

日期：2026-10-15

状态：设计讨论稿，尚未实施。关联语义暂按「继承选定会话的项目和知识、独立运行」设计，已向用户发出选择问题；用户若要求共用原会话，需要重新评估停止、归档和执行权限边界。

本设计接续已实现的个人 Codex / Claude Code 会话桥接，替代 2026-10-14 FF 设计中的「入群即在群内选择项目/工具/模型」流程。个人 AA 工作群不改用辅助群模式。

## 1. 本轮变更

- 所有者把机器人加入普通群后，机器人私聊所有者，请其选择关联已有 Codex 或 Claude 会话。
- 辅助群的逻辑会话显示名继续为 `FF-{群名}`。
- 辅助群只处理真实 @ 当前机器人的人类消息；一人一机器人群也遵循该规则。
- 辅助群回答卡片底部只显示「停止」「刷新」两个按钮，包括运行中、成功、失败、被停止后的卡片。
- 权限统一采用固定辅助策略，复用多工具会话发现、路由、队列、停止、刷新和账本。
- 保留先前已确认的权限范围：本机项目只读、所有外部机器可执行、同事可触发、所有脚本与已有产物可部署、其他源码文件不能复制部署；允许云端分析与飞书代码片段。
- 保留所有者 `@机器人 退出` 后退群并归档辅助会话的要求。

- 私聊控制台已有会话候选、分页和所有者相关校验；不能原样复用「为所选会话新建个人群」的动作，需要新增「关联到待处理辅助群」动作。
- `src/card/run-renderer.ts` 当前统一显示停止、设置、刷新、分叉、归档，适合增加辅助群渲染策略。

## 3. 入群 → 私聊选择 → 启用

1. 根据 chat ID 和创建来源，先排除桥接主动创建的个人群及 AA 自动镜像群。
2. 校验加机器人的是应用所有者。其他人拉入的群先不开放任务；不给任意邀请者发送所有者的会话列表。
3. 幂等保存 `pending-owner-link` 记录和通知待办。查询真实群名，用 `FF-{群名}` 登记逻辑辅助会话；未关联前不调用模型、不读取项目代码、不下载任务附件。
4. 私聊所有者发送「为群〈群名〉关联会话」卡片：先选择 Codex/Claude，再分页选择现有会话。候选显示会话名称、工具和工作目录，原始历史仅供所有者预览，不发送到辅助群。
5. 选择及确认动作校验真实操作者是所有者，token 绑定 appId、chatId、加入代次、候选来源和有效期。确认前再次验证机器人仍在群内、会话与目录仍可用、该群未被重新关联。
6. 继承所选会话的 cwd、工具和已验证模型作为关联数据，建立独立受限运行绑定，完成后标记 active。辅助群只收到简短启用通知，不自动回放原历史。
7. 私聊失败保存待办并重试；所有者可在机器人私聊面板找到「待关联辅助群」。机器人在群内最多提示尚待所有者配置，不公开会话目录和候选详情。重复入群事件和服务重启不重复创建会话或刷屏。

## 4. 关联的默认语义

记录两个不同引用：

- `sourceRef = {toolId, sourceId, nativeId}`：所有者选定的已有会话，提供项目和关联知识。
- `runRef = {toolId, isolatedSourceId, nativeId}`：辅助群实际运行的独立会话，使用固定限制，不沿用原执行权限。

主方案采用「所选历史的已完成部分生成知识快照/摘要 + 同项目只读访问」。所有者在私聊关联确认时能看到共享范围，必要时查看摘要；确认绑定意味着授权把该范围的知识用于该群回答。摘要带源引用、截点和版本。原始历史中的工具指令、系统配置、环境变量、密钥及附件不直接复制成运行配置。

不直接恢复原会话、不写回原历史、不镜像原会话未来的个人消息。同一来源可以关联多个辅助群，各群运行 ID 和后续上下文独立。原会话即使处于 full，也不改变辅助策略。

不必为首版实现通用知识库、向量检索、跨项目权限矩阵或多工具原生 fork。使用摘要和文件读取即可；摘要不能替代完整历史，详细上下文不足时明确说明。未来需要原生 fork 时，也必须重新验证权限及配置继承，不能默认为安全捷径。

项目目录默认来自选定来源 cwd，不另向群成员开放项目选择面板。若 cwd 不存在、是个人 home/系统敏感路径，或来源项目不明确，则在私聊请所有者修正，不能退回 `/home/pc/code` 全量访问。

关联建立时记录来源信息和项目，不持续跟随源会话的目录/工具/模型变更。更新知识或更换来源仅由所有者在私聊发起，并创建新一代辅助运行绑定，归档旧辅助会话。卡片「刷新」不执行此动作。

## 5. 辅助群身份与按钮

群类型用可信持久化字段区分，例如 `kind=auxiliary`、`kind=personal`；群名和邀请者姓名不决定权限。个人建群 REST 响应与入群事件交错时，先作为未定来源处理，不抢先关联或继承 full。

辅助记录保存 appId、chatId、加入代次、kind、ownerId、状态、sourceRef、runRef、cwd、knowledgeSnapshotRef、policyVersion 和通知/归档/退群步骤。

群回答的底部只有两个按钮：

- 停止：停止该辅助运行的当前任务及可撤销远程操作，不停止 sourceRef 对应的个人会话；无运行时禁用或明确提示已结束。不能把点击旧卡片解释成停止后来的无关运行。
- 刷新：读取该卡片/本群运行实际状态并更新显示，不重新提交问题、不重跑部署、不更新来源知识、不修改源会话。

辅助群不提供设置、换工具、改目录、分叉、归档按钮。仅隐藏 UI 不够：回调和文字指令入口也按辅助能力集合校验，伪造或旧卡片中的管理动作同样拒绝。

首版采用简单角色：群成员可提问和刷新；当前任务发起者与所有者可停止；所有者可私聊关联/改关联及执行退出。回调须核验真实点击者、群成员关系、group/run/message/generation 和有效期；不能复用所有者私聊 token 到群内执行。

## 6. 权限如何简化

### 6.1 统一一套辅助策略

不做每群不同权限和动态升权；群只保存来源及项目。所有辅助群固定为：只读项目、无通用本机命令、两项远程能力；个人群继续使用现有策略。使用一个可复用的受限运行模板，按任务挂载选定目录并隔离会话状态，不要求每群部署一套长期服务。

### 6.2 把本机读取与远程操作分开

受限分析器只提供项目内读取/检索。Claude 可以使用 `--restricted` 加显式 `--tools` 收窄内置工具，加载严格限定的 MCP 配置和受控设置；不能把 `--allowedTools` 当作工具可见范围，也不能只用 plan 或 bypassPermissions。实现前核验这些选项在当前版本的组合和恢复会话时仍有效。

Codex 采用经过核验的 read-only sandbox 和受控工具配置；不经共享 full 队列继续原 thread。两种工具都隔离 home、插件/hooks、个人 MCP、SSH/飞书凭据和可提升权限的进程通道；代码目录 OS 层只读，模型不获得通用本机 shell。网络不开放任意外传。

单独工具服务只暴露：

- `remote_exec(target, command, timeout)`：在外部机器执行；允许所有外部地址并允许同事触发，但解析结果不能是本机，SSH 选项不能注入本地执行/转发能力。
- `deploy(target, sourceRef, destination)`：从允许的脚本/产物来源部署文件，核验真实路径和文件身份；不允许模型直接运行 scp/rsync。

服务端注入群/会话/调用者身份并持有凭据；模型参数不能替换授权身份。这样不必给模型开通本机网络 shell，也不必给同事暴露 SSH 密钥。

### 6.3 简化文件规则，保留可验证边界

所有脚本继续允许外传；通过选定项目中的实际脚本路径或服务接收的脚本文本部署。现有产物使用构建清单/登记摘要确认；首版不接收任意路径、任意目录打包、任意压缩包。

避免首版实现通用递归压缩包扫描和语义 DLP：只允许可核验的单个脚本、已登记产物及已有可信清单的包；无法验证的包拒绝并说明原因，不能把其认定为产物。禁止改后缀、符号链接逃逸或内容替换绕过来源检查。

允许源码分析和飞书片段、并允许所有脚本，本设计不声称「源码内容绝不离开本机」；承诺针对非脚本源码文件及包含它们的未授权包的部署限制。

### 6.4 可选的最小首期范围

若用户希望进一步减少首期工作，可以只交付「私聊关联 + 只读回答 + 两按钮 + 退出归档」，暂不开放远程执行/部署。此选项会缩减先前已确认的能力，必须由用户选择，不能默认删除。

保持全部既定能力的推荐方案是固定辅助策略 + 复用沙箱模板 + 两项远程工具，不增加权限管理 UI、任意 shell 放行规则或每群专属服务。若工具或 OS 边界无法实现，禁用对应辅助能力并明确报告，不能退回 full。

## 7. 退出与兼容

所有者在辅助群真实 @ 并发送精确退出指令后，停止本群新请求，处理本群当前任务，归档 runRef 和辅助账本，再让机器人主动退群。原 sourceRef 会话及其个人工作群不归档、不停止；历史数据保留。

归档或退群部分失败持久化步骤并补偿，不能虚报成功；被移出群同样关闭辅助绑定。原生归档能力不一致时按工具标明：Codex 可原生归档，Claude 使用桥接归档并保留历史，不以删除历史替代。

AA 自动同步排除辅助运行会话，避免又为 FF 生成个人工作群；原会话的新回答只按原个人绑定分发，辅助输出只按 chatId + generation + runRef 分发。一个来源关联多个群不会触发已有个人原生会话的单绑定限制。

## 8. 实施点与验收

- 复用 `ToolRegistry.listSessions()` 和私聊候选列表，新增辅助关联动作、私聊待办及生命周期账本。
- 扩展绑定为 sourceRef/runRef，辅助状态与个人工作群分开；不能直接调用现有「创建所选会话群」动作。
- 渲染器增加固定辅助按钮集合，并贯穿 Codex/Claude 初次发送、流式更新、历史恢复、错误补发和刷新路径。
- 入口、回调、队列提交和工具服务共同校验辅助策略，不能只验证卡片。
- 验证：入群事件去重/事件竞态、私聊失败重试、所有者与来源校验、来源历史不写回、两个引擎目录继承、严格 @、两按钮各状态、旧卡片与伪造动作拒绝、源任务不被停止/归档、外部执行与本机拒绝、脚本产物可部署/其他源码拒绝、重启补偿。
- 本轮只变更设计文档，不表示已实现、已部署或权限限制已生效。
