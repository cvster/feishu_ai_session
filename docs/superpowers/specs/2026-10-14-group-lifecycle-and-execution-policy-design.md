# 飞书群自动会话与执行权限设计

日期：2026-10-14

状态：需求已澄清，设计待用户审阅；尚未修改产品代码、运行配置或部署服务。

## 1. 已确认需求

- 使用现有「Lennox飞书助手」，App ID 为 `cli_aa36351590381bcd`。
- 机器人被加入群时自动创建并持久化一个独立 Codex 会话，按群 ID 绑定。
- 群内只处理真实 @ 当前机器人的人类消息。普通聊天、@全员、纯文本写机器人名称均不触发；一人一机器人群也没有豁免。
- 群成员可以提出问题、触发外部机器执行和部署。
- 本机任务权限只读，禁止修改、删除本机项目源码，禁止执行本机项目脚本或本机构建。
- 外部机器不设置静态主机白名单；请求提供目的地址，使用已有且适用于该地址的登录凭据。授权不等于自动具备网络连通性或登录凭据。
- 所有脚本允许向外部署，包括项目中原有脚本和机器人生成的脚本。脚本是禁止源码文件外传规则的明确例外。
- 允许部署已有构建产物；其他源码文件及包含它们的打包文件禁止向外部署。
- 允许云端 Codex 分析本机源码，允许飞书回答包含必要代码片段。这不是「源码内容完全不出本机」的设计。
- 应用所有者发送 `@机器人 退出` 时，自动退出当前群并归档对应会话，群及历史消息保留。

## 2. 现有实现与缺口

依据部署目录 `/home/pc/lark-coding-agent-bridge` 和新核对的源码仓库 `/home/pc/code/CodexFeishu`：

- `src/bot/channel.ts` 使用群白名单和 profile 权限；未接入 SDK 的 `botAdded` 处理器。
- @ 过滤存在一人一机器人群的例外，需要给本模式增加严格过滤。
- `src/agent/types.ts` 已有归档接口，没有独立建会话接口。
- `packages/codex-core/src/lifecycle.ts` 已有可持久化的 `thread/start`、命名和历史验证流程，可以复用，不需要为了建会话发送虚构用户问题。
- `src/commands/index.ts` 的工作群完成流程会解散群，不能用来实现退出同事已有群。
- 普通群目前按 chat ID 共用上下文，话题群会按话题分离。本需求选每群一个会话，话题只作为消息引用和回复位置，不另建可执行会话。
- profile 当前为 `full`，且关联本机桌面会话。该运行方式不能作为同事群只读隔离的基础。
- AA 群同步和桌面回复同步需要尊重新群绑定策略，不能自动接管这些独立会话、恢复已退出群或向同事群镜像个人桌面会话。

## 3. 方案

在同一应用的桥接进程中增加群生命周期管理器与执行代理。继续由单个桥接连接接收事件，避免启动两个相同 App ID 的独立监听服务导致分发不确定。

群任务使用独立受限 Codex 运行环境，不复用桌面上具有 full 权限的会话、个人配置、插件和用户登录态。桥接仍可写自己的会话账本、日志和消息缓存；「本机只读」约束群任务工作负载，不阻止服务自身持久化状态。

### 3.1 入群和会话绑定

监听 `im.chat.member.bot.added_v1`，确认事件针对当前机器人，查询群信息并创建群记录。

记录键为 App ID + chat ID + 加入代次，包含：群名称、会话 ID、加入者、策略版本、状态、事件去重信息、归档与退群结果。状态为 `joining → active → leaving → archived`，另有可恢复的错误状态。

按群串行处理事件；第一次创建持久化空会话并命名为 `飞书群：<群名>`，校验会话可以读取后才标记 active。重复入群事件不新建会话；先收到 @ 消息但初始化未完成时先入账，绑定成功后只提交一次。

服务重启通过机器人所在群列表与账本进行核对，补偿漏失的加入和移出事件。无法确认当前群成员关系时不猜测为已退群，也不盲目创建重复会话。

重新入群创建新的代次和会话；旧归档历史保留，不自动恢复已归档的高权限会话。

### 3.2 消息入口

必须同时满足：群记录 active、发送者是人类、结构化 mentions 指向本机器人、消息 ID 未处理。

过滤在会话建立、模型提交、附件下载和队列写入之前执行。未 @ 消息不进入任务上下文；@全员或回复机器人但未 @ 也不触发。

群成员具备问答、远程执行与部署权限；应用所有者独占退出、提升本机权限、修改执行策略和账户配置。消息中的姓名或自称管理员不能改变角色。

同群请求进入同一会话，保留真实发言者信息并按队列串行提交；不同群不共享会话、附件缓存授权或任务结果。

### 3.3 本机只读与工具边界

使用独立 Codex home、只读 sandbox 与操作系统隔离，仅暴露允许分析的代码目录，不暴露个人 home、SSH 私钥、飞书密钥和桌面 app-server socket。检查并去掉继承的用户 hooks、额外 MCP、shell 环境及提权入口。

只读不是只加 system prompt。群任务仅获得受控本机读取/检索、远程执行、部署工具；禁止通用本机写文件、任意本机 shell、任意网络上传和直接 lark-cli 写入。飞书回复由桥接统一发出。

Linux 的 bubblewrap 已安装，可以作为文件系统隔离基础；网络、工具禁用和 broker 通道必须单独校验。支持的本机 Codex 协议应能够绑定受限工具；如果无法禁用不受控的 shell/网络或无法验证边界，就让受限模式拒绝启动，不能回退到 full。

只读模式不允许本机编译。生成运维脚本通过部署代理的脚本文本输入发送到远端；已有产物从本机读取发送。远端可生成自己的文件并执行任务。

### 3.4 外部机器执行

提供结构化执行工具：目标地址、端口、账户、远端目录、命令/脚本、超时时间；发起者和群/会话 ID 由桥接注入，不从模型参数获取授权身份。

不限制外部机器列表，但必须阻止目的地址解析成本机：localhost、回环、本机接口地址、IPv4/IPv6 别名、Unix socket、DNS 解析变化等。禁止通过模型参数开启本地命令、端口转发、任意 SSH 配置、ProxyCommand 或传递本机执行选项。目标核验与实际连接使用同一核验结果，避免解析检查后换地址。

代理持有独立远程执行凭据；模型不可读取凭据。SSH 服务身份按正常 known_hosts 校验，不因「允许所有机器」而忽略主机身份错误。缺少凭据或连接失败向当前群明确报告，不把任务回退到本机执行。

命令可在外部机器执行并回传输出。超时、取消和连接中断必须区分「确认未执行」「已执行」「执行结果未知」，未知状态不能自动重复执行。队列和日志记录请求 ID，避免事件重发造成重复部署。

外部机器自身的操作权限由其登录账户决定；机器人不会因为任务描述自动获得额外账户权限。

### 3.5 部署和源码文件导出

所有传输必须走部署代理，不能让模型直接使用 scp、rsync、curl 上传或任意 socket。

可接受的输入有：单个脚本、脚本文本、已登记的构建产物、仅包含允许文件的部署包。不使用「整个代码目录」或「任意文件」接口。

脚本类型用明确且可扩展的脚本格式列表及 shebang 识别；保留原始路径/来源，不因把 `.cpp` 重命名为 `.sh` 就放行。项目脚本的导出属于用户明确允许的例外，包括脚本语言本身的源码。

产物按构建产物登记/清单判断，不把任意扩展名文件或所有压缩包自动视为产物。对包内文件递归检查，禁止非脚本源码、`.git`、凭据和指向禁止文件的链接；无法检查的包不放行。

检查真实路径、符号链接、文件类型、文件身份和内容摘要；核验与读取使用固定文件句柄，避免核验后文件被替换。禁止打包时跟随链接逃逸，禁止从秘密目录读取内容；阻止以预览、附件、文件发送等其他工具绕过文件导出规则。

允许云端源码分析和飞书代码片段，因此本方案不声称阻止源码内容的所有信息流。允许所有脚本也意味着不能仅凭后缀证明脚本中不存在代码。可强制验证的承诺是：本机项目不可写、原始非脚本源码文件及含这些文件的包不能经受控传输工具部署。

### 3.6 退出和归档

`退出` 作为入口层确定性指令，仅在应用所有者真实 @ 时匹配，不交给模型猜测；同事发送相同指令不退群。

先持久化 leaving 并阻止该群新任务与工具调用。处理只属于该群的尚未执行队列和运行中的任务，释放其工具租约；不影响别的群或桌面任务。远端已脱离会话的任务不能谎称停止，记录实际状态。

归档所有属于当前群代次的会话并保存历史；随后仅将机器人自身移出群。群本身和其他成员不受影响。退群前可以发送执行结果提示；发送失败不改变记录中的真实状态。

退群失败保留 leaving 状态，报告失败并重试；归档失败不能声称完成，保留待归档记录。退出事件、API 响应和重启补偿允许顺序交错，按账本状态幂等收敛。

被别人移出群也关闭任务入口并归档。退出后禁止 AA 自动群同步把相同会话重新绑定或自动创建替代群。

## 4. 飞书权限与发布

已订阅机器人加入/移出事件和接收消息事件。上线前重新核验权限与线上订阅，不依赖旧检查结果。

主动退群接口 `im.chat.members.delete` 需要 `im:chat` 或 `im:chat.members:write_only` 中任一权限；它不是解散群，不需要申请解散群的管理权限。当前权限是否满足须通过后台实际授权再次核验，缺少时只申请所需权限。

仍使用真实 @ 消息，即使保留已授权的 `im:message.group_msg`，应用入口也会忽略其他消息。后台应用可用范围可能限制同事添加机器人；接入时明确报告可用范围问题，不自行扩大可用范围。

## 5. 实施拆分与兼容性

1. 新增群生命周期账本、入群建会话、严格 @ 入口和所有者退出流程。
2. 新增独立受限 Codex 环境、受控读取与远程执行/部署代理，并完成绕过测试。
3. 接通队列、回复同步和故障补偿；核验飞书权限，测试后部署桥接。

前两部分可以独立验证，但不能先把同事群接入现有 full 执行环境。新模式在安全工具边界未就绪时不对外开放。

既有个人 AA 群的迁移单独处理：不把新同事群绑定到已有个人桌面会话，也不把已有群突然批量归档。上线变更必须明确展示哪些现有群保持原策略、哪些转为本模式；用户当前提出的模式首先用于新拉入的群。

维护任务本身的源码修改、构建和桥接持久化不属于同事群任务的本机只读工作负载。只重启桥接服务，不重启 Codex 桌面或共享 writer。

## 6. 验收

- 入群即有可读取的持久化会话；重复事件和重启不产生重复会话。
- 普通消息、@全员、纯文本名称和未 @ 的回复不调用模型，单人群同样适用。
- 多群并发只进入对应会话；入群与消息同时到达不丢失或重复提交。
- 同事可触发远程操作，但不能退出机器人、提权或修改账户/策略。
- 本机源码修改、执行本机脚本、直接 SSH/上传、访问个人凭据均失败；不能通过恢复 full 会话或 /config 绕过。
- 远程正常执行；指向本机的 IPv4、IPv6、别名和转发请求被拒绝；失败不回退本机。
- 所有确认的脚本格式和已登记产物能部署；非脚本源码、源码包、伪装文件、链接逃逸和替换文件被拒绝。
- 允许云端分析及飞书片段回复，与禁止源码文件传输的规则一致。
- 所有者 `@机器人 退出` 后机器人不在群中，会话已归档，其他群和群历史保留；断网、归档失败、退群失败能够恢复且不虚报完成。
- 权限核验、核心单元与集成检查、类型检查和构建通过后部署；最后验证服务连接及真实群事件。
