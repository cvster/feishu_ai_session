# 飞书群自动会话与执行权限设计

日期：2026-10-14

状态：延期参考。用户已明确本次只实现个人会话的 Codex / Claude Code 工具选择与 AA 自动建群；当前设计见 `2026-10-14-multi-tool-personal-sessions-design.md`。本文件中的 FF/同事群/受限环境不纳入本次。

2026-10-15：用户重新启动辅助群设计，并改为入群后私聊所有者选择关联已有会话、群回答仅保留停止/刷新按钮。当前讨论稿见 `2026-10-15-auxiliary-group-session-link-design.md`；本文保留为前期参考。

## 1. 已确认需求

- 使用当前 profile 绑定的飞书 CLI 应用机器人，App ID 从 profile 配置读取；管理身份按该应用的所有者解析。
- 机器人被加入群时自动登记并持久化一个独立模型会话，首期支持 Codex 与 Claude Code，按群 ID 绑定；会话名为 `FF-{群名}`。
- 群内只处理真实 @ 当前机器人的人类消息。普通聊天、@全员、纯文本写机器人名称均不触发；一人一机器人群也没有豁免。
- 群成员可以提出问题、触发外部机器执行和部署。
- 本机任务权限只读，禁止修改、删除本机项目源码，禁止执行本机项目脚本或本机构建。
- 外部机器不设置静态主机白名单；请求提供目的地址，使用已有且适用于该地址的登录凭据。授权不等于自动具备网络连通性或登录凭据。
- 所有脚本允许向外部署，包括项目中原有脚本和机器人生成的脚本。脚本是禁止源码文件外传规则的明确例外。
- 允许部署已有构建产物；其他源码文件及包含它们的打包文件禁止向外部署。
- 允许云端 Codex 分析本机源码，允许飞书回答包含必要代码片段。这不是「源码内容完全不出本机」的设计。
- 应用所有者发送 `@机器人 退出` 时，自动退出当前群并归档对应会话，群及历史消息保留。

## 2. 现有实现与缺口

依据部署目录 `/home/pc/lark-coding-agent-bridge` 和新核对的源码仓库 `/home/pc/code/CodexFeishu`：

- `src/bot/channel.ts` 使用群白名单和 profile 权限；未接入 SDK 的 `botAdded` 处理器。
- @ 过滤存在一人一机器人群的例外，需要给本模式增加严格过滤。
- `src/agent/types.ts` 已有归档接口，没有独立建会话接口。
- `packages/codex-core/src/lifecycle.ts` 已有可持久化的 `thread/start`、命名和历史验证流程，可以复用，不需要为了建会话发送虚构用户问题。
- `src/commands/index.ts` 的工作群完成流程会解散群，不能用来实现退出同事已有群。
- 普通群目前按 chat ID 共用上下文，话题群会按话题分离。本需求选每群一个会话，话题只作为消息引用和回复位置，不另建可执行会话。
- profile 当前为 `full`，且关联本机桌面会话。该运行方式不能作为同事群只读隔离的基础。
- AA 群同步和桌面回复同步需要尊重新群绑定策略，不能自动接管这些独立会话、恢复已退出群或向同事群镜像个人桌面会话。

## 3. 方案

在同一应用的桥接进程中增加群生命周期管理器与执行代理。继续由单个桥接连接接收事件，避免启动两个相同 App ID 的独立监听服务导致分发不确定。

群任务使用所选执行工具的独立受限运行环境，不复用桌面上具有 full 权限的会话、个人配置、插件和用户登录态。桥接仍可写自己的会话账本、日志和消息缓存；「本机只读」约束群任务工作负载，不阻止服务自身持久化状态。

### 3.1 入群和会话绑定

监听 `im.chat.member.bot.added_v1`，确认事件针对当前机器人，查询群信息并创建群记录。

记录键为 App ID + chat ID + 加入代次，包含：群名称、会话 ID、加入者、群来源、项目 ID、知识关联、策略版本、状态、事件去重信息、归档与退群结果。状态为 `joining → active → leaving → archived`，另有可恢复的错误状态。

按群串行处理事件；第一次建立逻辑会话并命名为 `FF-{群名}`，按 3.1.4 的配置选择初始化后端；Codex 空会话验证和 Claude 的待初始化状态分别记录。后端具备运行条件并校验成功后才标记 active。重复入群事件不新建会话；先收到 @ 消息但初始化未完成时先入账，绑定成功后只提交一次。

服务重启通过机器人所在群列表与账本进行核对，补偿漏失的加入和移出事件。无法确认当前群成员关系时不猜测为已退群，也不盲目创建重复会话。

重新入群创建新的代次和会话；旧归档历史保留，不自动恢复已归档的高权限会话。

### 3.1.1 群来源与 FF 命名

群类型依赖持久化来源字段，不能通过群名、加入者是不是所有者、群成员数量或是否 @ 推断。

- `external-joined`：现有普通群被人拉入机器人，创建 `FF-{群名}` 新会话并采用新受限策略。所有者手动建群再加机器人也属于此类型。
- `owner-session-created`：桥接的个人建群流程（私聊面板、`/new chat`）创建的会话群，保留明确记录的个人工作群策略。
- `desktop-session-mirror`：AA 自动同步生成的群，绑定现有桌面会话，保留个人会话策略和已有身份。
- 来源未知的旧记录不能因为外观像 AA 或 FF 而获得个人权限；通过已有账本及创建记录迁移，无证据时作为受限待确认状态。

所有建群流程必须写入创建意图和已返回 chat ID，在入群事件与 REST 响应交错时进行串行合并和来源核对；来源尚未确认的群不能提前继承 full 权限或绑定个人会话。只靠定时等待几秒不解决这类竞态。

FF 名称是显示名，身份用 App ID、chat ID 和加入代次识别；同名群不混淆。外部群改名更新其 FF 会话名，但不改变权限、知识授权和项目绑定；个人会话名反向变化不改外部群名。

### 3.1.2 项目文件夹选择

入群时立即登记 FF 逻辑会话，但初始处于「项目未选择」状态；后端会话按照执行工具能力初始化。工作目录为群专属的中性状态目录，不默认开放 `/home/pc/code` 全部项目；在该状态下可回答通用问题和已授权资料问题，项目文件读取和部署源文件选择不可用。

入群提示提供「选择项目」卡片。项目注册表复用现有命名工作目录作为候选输入，再增加明确的项目 ID、规范化真实目录、知识集合、产物来源和授权信息；注册表由所有者维护。FF 群成员只能看到你给该群开放的项目，不能输入任意本机绝对路径来扩大权限。

所有者在当前群确认项目绑定；同事可以申请切换或从你明确授权给该群的可选项目中选择。初版默认由所有者确认，避免项目授权随着聊天内容改变。按群名推测项目只用于推荐，不自动授予访问。

绑定保存 `chatId → projectId → readRoots/knowledge/artifacts`，运行器只读挂载相应目录。项目目录解析和工具访问都校验真实路径与链接，不以 cwd 作为安全边界。

选择项目或项目切换后需要建立相应挂载环境。若群会话已读取过另一个项目，归档该会话并建立同名的新一代 FF 会话，避免旧上下文残留；群始终只保留一个当前活跃绑定。旧记录保留，未经授权不注入新会话。

### 3.1.3 与现有会话知识关联

独立会话不自动继承你的个人桌面历史。知识关联单独记录，不能用「继续已有会话」或 fork full 会话实现共享。

同一项目可共享代码只读视图、正式文档和你批准的项目摘要。需要关联具体 AA/个人会话时，由所有者选定来源和允许共享的内容，生成可共享摘要并确认后加入项目知识集合；记录源会话 ID、生成时间、来源位置与知识版本。不得把原始历史、附件、个人凭据或源会话执行策略自动带入 FF。

新增工具为当前群检索已授权知识集合，每次检索按群项目授权检查，不提供全量桌面会话搜索。回答给出引用及时间；来源资料中的指令作为数据处理，不改变运行权限。

例如：`FF-OTA联调群` 绑定 OTA 项目，只读 OTA 文件夹，并关联你批准的 `AA-ota-模型下载` 项目摘要；提问时可以利用这些知识，但不会把群消息发进原 AA 会话。

知识关系可以随项目更新，采用按需读取和版本记录，避免每轮拼入全部历史。归档源会话不自动删除已批准摘要；撤销共享则停止检索，并替换可能已经持有已撤销内容的 FF 会话上下文。入群、选择项目和关联知识是三个独立步骤。

### 3.1.4 创建会话时选择执行工具与模型

新增需求：同一个飞书机器人同时支持 Codex、Claude Code 等执行工具，创建 FF 会话时选择工具与模型；模型选择不得改变安全策略、群来源和项目授权。

现有项目已有 `CodexAdapter`、`ClaudeAdapter`、统一 `AgentEvent` 及模型选项，但运行时 profile 只实例化一个 adapter，executor 也固定 agent。需要把 profile 的 agent/model 改为默认值，将每个 FF 会话的选择保存为独立路由，避免一个群改模型影响所有群。

入群立即创建名为 `FF-{群名}` 的桥接逻辑会话并展示配置卡片：项目、执行工具、具体模型；工具默认为当前已启用的 Codex，模型为该工具的已验证默认值。卡片选择发生在首次任务执行前，由所有者或明确授权的群配置人员确认。同事仍可在配置完成后触发任务。未确认项目不提供项目代码访问。

原生后端会话初始化由适配器完成。Codex 可以持久化空 thread；Claude 先分配逻辑绑定/会话 ID，原生历史在首条真实请求产生。不能发送虚构用户问题来伪造「空会话已创建」。统一状态面板区分「已登记、待配置、待后端初始化、可执行、运行中、已归档」。对 Claude 的原生名称、会话 ID 和持久化参数，以本机 CLI 支持能力核验后使用。

模型注册表以执行工具/供应商/账户配置为维度，包含模型 ID、显示名称、支持的推理参数、附件/工具能力及验证状态。Codex 可查询已认证后端的模型列表；Claude 使用维护的候选和当前账户/CLI验证，不能假定有统一 models/list API。已有静态列表仅为候选，不保证模型已获授权。模型不可用时保留原选择并报告原因，不静默改用其他供应商或降级模型。

逻辑绑定保存 `logicalSessionId, chatId, generation, engineId, modelId, modelParams, credentialProfileRef, nativeSessionId, projectId, knowledgeRefs, policyVersion`。凭据只保存服务端引用。每次任务读取该群绑定快照，凭据、MCP配置与运行目录由可信服务选择，模型和用户文本不能提供任意配置路径或参数。

一个飞书监听进程配合执行工具注册表及按会话分发的 executor；保持统一消息去重、队列、回复、工具授权、并发管理、退出和归档账本。Codex 的 queue 和完成观察逻辑保留为适配器能力，Claude 使用本机 CLI 流式事件，不将「Codex队列已接收」当作其他工具的成功标准。

扩展统一适配器生命周期：能力与认证检测、模型候选/验证、创建或登记、运行/恢复、命名、停止、归档。原生能力不支持的操作由桥接账本实现并明确标记，例如 Claude 初版归档仅关闭桥接绑定并保留历史文件，不冒充已经执行 Codex 的原生归档，也不调用删除命令代替归档。

同工具内换模型仅影响后续任务，保留该群历史，核验当前 CLI 支持恢复时指定模型且权限未变化；记录实际生效模型。已有任务不在中途切换。跨工具切换创建新一代逻辑/原生绑定，保留旧历史；按同群已有知识授权提供摘要接续，不复用别的工具的原生 ID，也不复制个人会话历史。切换操作由所有者或显式授权的配置人员执行。

所有工具必须通过同一受限运行器和远程/部署代理。Claude 的 `plan` 模式不能单独当作只读保证，也不能为使远程工具工作而开启 `bypassPermissions`；实际可用工具、MCP来源和配置继承显式限定，OS层与代理层执行同样的限制。未通过隔离验收的执行工具不出现在可用选择列表。

首期支持 Codex 与 Claude Code；其他供应商通过新增执行适配器或 API agent 适配器接入，不把任意模型 ID 填进现有 Codex 适配器。只支持文本回复、不支持受控工具调用的模型可以标记为「仅问答」，不能展示为可远程执行。Codex和Claude的认证、账户权限及可用模型分别校验；安装CLI不等于已经登录或拥有指定模型。

统一管理位置为飞书的会话列表和状态面板。Claude 会话不是 Codex 原生 thread，不能承诺它会出现在 Codex Desktop 的原生会话列表；桥接保留跨工具的 FF 会话名与逻辑记录。

### 3.2 消息入口

必须同时满足：群记录 active、发送者是人类、结构化 mentions 指向本机器人、消息 ID 未处理。

过滤在会话建立、模型提交、附件下载和队列写入之前执行。未 @ 消息不进入任务上下文；@全员或回复机器人但未 @ 也不触发。

群成员具备问答、远程执行与部署权限；应用所有者独占退出、提升本机权限、修改执行策略和账户配置。消息中的姓名或自称管理员不能改变角色。

同群请求进入同一会话，保留真实发言者信息并按队列串行提交；不同群不共享会话、附件缓存授权或任务结果。

### 3.3 本机只读与工具边界

使用独立执行工具配置目录、显式工具限制与操作系统只读隔离，仅暴露允许分析的代码目录，不暴露个人 home、SSH 私钥、飞书密钥和桌面 app-server socket。检查并去掉继承的用户 hooks、额外 MCP、shell 环境及提权入口。

只读不是只加 system prompt。群任务仅获得受控本机读取/检索、远程执行、部署工具；禁止通用本机写文件、任意本机 shell、任意网络上传和直接 lark-cli 写入。飞书回复由桥接统一发出。

每个 FF 群独立保存所选执行工具的配置目录、上下文、附件和运行账本。受限运行器与桥接/执行代理分属不同进程及权限域；它只能看到按该群项目授权的只读挂载。只读设置同时在 Codex sandbox 和 OS 文件系统层生效，不能在聊天或卡片操作中升为 full。

Linux 的 bubblewrap 已安装，可以作为文件系统隔离基础；网络、工具禁用和 broker 通道必须单独校验。网络只提供受控模型访问和本群工具请求，模型访问凭据由服务认证层管理；文件读取工具不暴露凭据目录。执行代理接收结构化请求并注入群身份，不能给受限运行器通用的本机 shell 或文件读取代理接口。支持的本机 Codex 协议应能够绑定受限工具；如果无法禁用不受控的 shell/网络或无法验证边界，就让受限模式拒绝启动，不能回退到 full。

只读模式不允许本机编译。生成运维脚本通过部署代理的脚本文本输入发送到远端；已有产物从本机读取发送。远端可生成自己的文件并执行任务。

### 3.4 外部机器执行

提供结构化执行工具：目标地址、端口、账户、远端目录、命令/脚本、超时时间；发起者和群/会话 ID 由桥接注入，不从模型参数获取授权身份。

不限制外部机器列表，但必须阻止目的地址解析成本机：localhost、回环、本机接口地址、IPv4/IPv6 别名、Unix socket、DNS 解析变化等。禁止通过模型参数开启本地命令、端口转发、任意 SSH 配置、ProxyCommand 或传递本机执行选项。目标核验与实际连接使用同一核验结果，避免解析检查后换地址。

代理持有独立远程执行凭据；模型不可读取凭据。SSH 服务身份按正常 known_hosts 校验，不因「允许所有机器」而忽略主机身份错误。缺少凭据或连接失败向当前群明确报告，不把任务回退到本机执行。

命令可在外部机器执行并回传输出。超时、取消和连接中断必须区分「确认未执行」「已执行」「执行结果未知」，未知状态不能自动重复执行。队列和日志记录请求 ID，避免事件重发造成重复部署。

外部机器自身的操作权限由其登录账户决定；机器人不会因为任务描述自动获得额外账户权限。

### 3.5 部署和源码文件导出

所有传输必须走部署代理，不能让模型直接使用 scp、rsync、curl 上传或任意 socket。

可接受的输入有：单个脚本、脚本文本、已登记的构建产物、仅包含允许文件的部署包。不使用「整个代码目录」或「任意文件」接口。

脚本类型用明确且可扩展的脚本格式列表及 shebang 识别；保留原始路径/来源，不因把 `.cpp` 重命名为 `.sh` 就放行。项目脚本的导出属于用户明确允许的例外，包括脚本语言本身的源码。

产物按构建产物登记/清单判断，不把任意扩展名文件或所有压缩包自动视为产物。对包内文件递归检查，禁止非脚本源码、`.git`、凭据和指向禁止文件的链接；无法检查的包不放行。

检查真实路径、符号链接、文件类型、文件身份和内容摘要；核验与读取使用固定文件句柄，避免核验后文件被替换。禁止打包时跟随链接逃逸，禁止从秘密目录读取内容；阻止以预览、附件、文件发送等其他工具绕过文件导出规则。

允许云端源码分析和飞书代码片段，因此本方案不声称阻止源码内容的所有信息流。允许所有脚本也意味着不能仅凭后缀证明脚本中不存在代码。可强制验证的承诺是：本机项目不可写、原始非脚本源码文件及含这些文件的包不能经受控传输工具部署。

### 3.6 退出和归档

`退出` 作为入口层确定性指令，仅在应用所有者真实 @ 时匹配，不交给模型猜测；同事发送相同指令不退群。

先持久化 leaving 并阻止该群新任务与工具调用。处理只属于该群的尚未执行队列和运行中的任务，释放其工具租约；不影响别的群或桌面任务。远端已脱离会话的任务不能谎称停止，记录实际状态。

归档所有属于当前群代次的会话并保存历史；随后仅将机器人自身移出群。群本身和其他成员不受影响。退群前可以发送执行结果提示；发送失败不改变记录中的真实状态。

退群失败保留 leaving 状态，报告失败并重试；归档失败不能声称完成，保留待归档记录。退出事件、API 响应和重启补偿允许顺序交错，按账本状态幂等收敛。

被别人移出群也关闭任务入口并归档。退出后禁止 AA 自动群同步把相同会话重新绑定或自动创建替代群。

## 4. 飞书权限与发布

已订阅机器人加入/移出事件和接收消息事件。上线前重新核验权限与线上订阅，不依赖旧检查结果。

主动退群接口 `im.chat.members.delete` 需要 `im:chat` 或 `im:chat.members:write_only` 中任一权限；它不是解散群，不需要申请解散群的管理权限。当前权限是否满足须通过后台实际授权再次核验，缺少时只申请所需权限。

仍使用真实 @ 消息，即使保留已授权的 `im:message.group_msg`，应用入口也会忽略其他消息。后台应用可用范围可能限制同事添加机器人；接入时明确报告可用范围问题，不自行扩大可用范围。

1. 新增群生命周期账本、FF创建配置卡片、按会话选择执行工具/模型、严格 @ 入口和所有者退出流程。

既有个人 AA 群的迁移单独处理：不把新同事群绑定到已有个人桌面会话，也不把已有群突然批量归档。上线变更必须明确展示哪些现有群保持原策略、哪些转为本模式；用户当前提出的模式首先用于新拉入的群。

维护任务本身的源码修改、构建和桥接持久化不属于同事群任务的本机只读工作负载。只重启桥接服务，不重启 Codex 桌面或共享 writer。

## 6. 验收

- 入群即有命名为 `FF-{群名}` 的可读取持久化逻辑会话；后端状态明确，重复事件和重启不产生重复会话。
- 两个群可分别选择 Codex 和 Claude；模型选择与权限策略彼此独立，一个群的模型设置不影响另一个群。
- 模型不可用不静默切换；跨工具切换不复用原生会话ID，同群知识按授权接续。
- Codex和Claude均通过相同本机只读与传输绕过验收；Claude退出采用明确的桥接归档语义并保留历史。
- 同名群、群改名、所有者手动加机器人和桥接自己建群均按来源记录正确分类，不串用 AA/full 会话；来源未定的事件不提权。
- 未选项目不开放代码根目录；绑定后只能读取选定项目，切换与撤销授权不保留可继续访问的旧上下文。
- 知识关联只检索已批准的项目资料/摘要，不自动读取其他个人会话历史；回答包含可追溯来源。
- 普通消息、@全员、纯文本名称和未 @ 的回复不调用模型，单人群同样适用。
- 多群并发只进入对应会话；入群与消息同时到达不丢失或重复提交。
- 同事可触发远程操作，但不能退出机器人、提权或修改账户/策略。
- 本机源码修改、执行本机脚本、直接 SSH/上传、访问个人凭据均失败；不能通过恢复 full 会话或 /config 绕过。
- 远程正常执行；指向本机的 IPv4、IPv6、别名和转发请求被拒绝；失败不回退本机。
- 所有确认的脚本格式和已登记产物能部署；非脚本源码、源码包、伪装文件、链接逃逸和替换文件被拒绝。
- 允许云端分析及飞书片段回复，与禁止源码文件传输的规则一致。
- 所有者 `@机器人 退出` 后机器人不在群中，会话已归档，其他群和群历史保留；断网、归档失败、退群失败能够恢复且不虚报完成。
