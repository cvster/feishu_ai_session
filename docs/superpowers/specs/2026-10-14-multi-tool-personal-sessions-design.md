# 个人会话的 Codex / Claude Code 双工具设计

日期：2026-10-14

状态：已实施，代码交付阶段；尚未部署。替代前一份方案的实施范围；FF入群、同事使用、受限环境和知识共享均延期。

实施说明：`src/tools` 提供注册表、会话元数据提供器、持久化工具绑定、按会话控制视图和原生会话锁；现有执行器、群同步和渲染器共用。Claude 正式名称使用本机 CLI JSONL `custom-title` 兼容读取，首次真实请求前预留 UUID。Claude 归档仅在桥接账本中记录，原生历史保留。Linux 原生恢复前用 `/proc` 保守检查同目录 Claude 进程，未知状态拒绝请求；无法消除外部进程在检查后启动的竞争。本阶段未实现 Claude 外部终端回复镜像、双向改名和每工具单独并发配额，继续使用共享并发池。后续工具仍需扩展配置中的工具枚举及能力实现，通用发现/绑定/路由接口可复用。

## 目标

- 当前飞书机器人同时服务 Codex 与 Claude Code，不启动两个相同 App ID 的监听服务。
- 主动创建会话/工作群时提供「执行工具」选择：Codex 或 Claude Code，默认 Codex。
- 工具只在创建时选择；创建成功后固定，不增加会话中切换工具的入口。
- Codex 中名称以大写 AA 开头的会话继续自动创建对应群。
- Claude Code 中名称以大写 AA 开头的会话也自动创建对应群，并恢复原 Claude 会话。
- 工具、会话发现、群同步、会话绑定、执行和回复清晰解耦，便于后续注册其他工具。
- 现有个人群权限、消息触发方式、工作目录规则和 Codex 桌面联动保持兼容。

具体模型先沿用各工具默认值或现有设置。本次新增的是工具选择，不新增跨供应商自动降级、模型市场或运行中切换工具。

## 已核对的代码

- 已有 `CodexAdapter` 和 `ClaudeAdapter`，以及统一 `AgentEvent`。
- `createRuntimeAgent()` 和 `RunExecutor` 当前固定单个工具，不能按群分发。
- `newChatCreationCard()` 和欢迎卡片写死 Codex；创建表单的模型设置会保存到 profile，需要避免把新会话的选择变成全局切换。
- `aa-session-groups.ts` 当前硬编码 Codex 历史、thread ID 和权限能力。
- `session/history.ts` 已有 Claude 本地历史读取，但只返回 session ID、预览、更新时间；没有正式名称、完整来源与生命周期信息，不足以用于 AA 发现。
- 会话目录已有 `agentId`，可以迁移；`SessionStore`、归档墓碑和同步键仍需统一带工具身份。
- 本机已安装 Codex 与 Claude Code CLI。安装不代表认证和所有功能已可用，需要独立检查。

## 方案选择

采用「单飞书入口 + 工具注册表 + 按会话路由 + 通用 AA 群同步」。

不复制两套群管理代码，也不让 profile.agentKind 的变化承担群级路由。profile 中的原有 agentKind 保留为默认和旧数据迁移依据，不再代表所有新群只能使用这一种工具。

执行工具一旦创建绑定即固定；恢复记录必须显式使用绑定中的工具和原生会话 ID，禁止 `--continue` 随意恢复某工具的最近会话。

## 分层职责

### 1. 飞书入口和创建界面

负责收消息、卡片、按钮授权、群信息及群成员，不了解 Codex thread 或 Claude transcript 的内部格式。

创建表单显示群名、工作目录和「执行工具」；默认 Codex，Claude Code 按独立可用状态展示。失败时说明缺少 CLI、认证或功能，不默默回退到 Codex。

创建 API 以结构化参数提交 `toolId, name, cwd, settings`；先校验工具和目录，再建群和持久化绑定。无需伪造用户提问来强行创建原生历史。CLI或旧按钮未传工具字段时按原配置默认值迁移；当前环境默认仍是 Codex。

新建绑定可处于 `pending-native`：已有工作群和工具选择，第一条真实请求才创建原生会话。Claude 如可预分配 UUID，适配器保存该 ID并在首次运行时传入受支持参数；不能把预分配 ID 描述成已存在的可恢复历史。

欢迎卡片、状态面板、恢复列表展示实际工具。工具选择不能改变其他群的模型、权限或工作目录。

### 2. 工具注册表

每个工具插件由小接口组合，提供：

- `SessionProvider`：发现/读取本工具会话元数据，解析真实工作目录，按能力提供命名和历史读取。
- `AgentRunner`：新建或恢复运行，发送请求，输出统一事件，停止本次任务。
- `LifecycleProvider`：按支持能力实现命名、归档和原生状态查询。
- `ExternalObserver`：可选的原生终端/桌面任务观察，不要求所有工具具有 Codex 的队列和通知协议。
- `capabilities`：明确创建空历史、排队、外部观察、命名、归档等能力，缺少能力时使用明确的桥接行为。

注册表按稳定 `toolId` 取插件。每个插件配置自己的 binary、认证和历史来源；可独立不可用。新增工具仅注册新插件和配置，通用群同步与路由层不增加新的 provider 专属条件分支。

### 3. 统一会话与绑定目录

`SessionRef` 的身份是 `(toolId, sourceId, nativeSessionId)`。sourceId 指向配置好的本地账户/数据源，不能只用显示名称、cwd 或裸 UUID 去重。

统一元数据包含原生 ID、工具、来源、正式名称、工作目录、创建/更新时间、归档状态和可验证的运行状态。无法确认状态时记录 unknown，不用文件 mtime 伪装 idle 或 completed。

群绑定独立保存 `chatId, origin, toolId, sourceId, nativeSessionId?, cwd, toolSettings, status, generation`。origin 区分主动创建和 AA 导入。群ID为消息路由入口，原生ID为对应工具的恢复入口。

同一 native ID 出现在不同工具或数据源中，必须是不同会话。归档墓碑、去重、名称同步、消息投递水位、锁和回调令牌使用同一身份规则。

旧 Codex 绑定原样迁移为 Codex来源；已有明确 agentId 的旧Claude记录保持Claude。没有工具身份的旧记录使用历史profile配置及记录验证，来源有冲突则暂停并报告，不猜测后将消息发给错误工具。迁移必须保留原有会话ID与群绑定。

### 4. 通用 AA 群同步

同步器遍历已启用插件的 SessionProvider，得到统一元数据，再执行现有 AA 前缀、目录校验、群可见性、去重、创建和绑定流程。一个插件扫描失败不阻止其他插件同步；飞书群列表无法查询时不盲目创建群。

CodexProvider 复用现有历史读取。ClaudeProvider 首选经过版本验证的官方会话元数据读取能力；官方 Agent SDK 提供本地会话列表、信息和改名操作，不需要启动一次模型任务才能列出历史。若采用本地JSONL兼容读取，封装在ClaudeProvider内，并以真实CLI生成的格式测试。

Claude 的 AA 判断使用真实会话名称（customTitle或明确持久化名称），不能使用第一条问题、preview或自动摘要替代。没有可验证正式名称的Claude会话暂不参与AA同步。排除子代理会话，读取历史文件中未写完行时不清空原有结果。

AA规则保持现有大写匹配与前导空白处理。现有版本族合并规则按 `(toolId, sourceId, family)` 分区，Codex的 `AA任务2` 不能升级/接管Claude的 `AA任务1`。

同一个工具会话只自动绑定一个当前应用下的群；多轮扫描和重启不重复建群。两个工具里的同名AA会话各建各的群，显示名使用现有重名处理，并在欢迎卡片和状态面板明确工具。群名不是身份键。

从AA原生会话导入时直接使用原会话的cwd和原生ID，工具由来源确定，不弹出再次选择工具。主动创建一个AA命名会话后，只要已经绑定群，就不能再被扫描器创建第二个群。

### 5. 按会话执行

消息入口解析绑定，生成不可变的 `ResolvedSessionContext`：工具、原生会话ID、cwd、有效设置、权限和来源。命令处理、运行器、面板、恢复和归档都使用该上下文，不能继续依赖profile.agentKind或单个全局adapter。

`AgentRouter` 向注册表查询AgentRunner，传给现有运行管理/进程池。运行锁按原生SessionRef建立，防止两个桥接群或入口同时写同一会话。并发限额继续统一管理，并允许每工具设置限额。

Codex保留已有native queue、请求接收确认、统一回复同步器和桌面writer协作。Claude恢复使用绑定原生ID，其stream-json由适配器转换成统一text/tool/usage/result/error事件。禁止通过切换工具或自动fork掩盖恢复失败。

外部Claude终端仍在运行同一会话时，适配器必须使用可验证占用状态或工具提供的合法接收机制；无法确认安全写入就提示稍后继续，不能假定桥接锁约束了外部终端。无法确认请求是否执行时不自动重发。

### 6. 回复、名称和生命周期

桥接内发起的Codex/Claude运行都通过统一事件与飞书回复渲染器回群。原生终端/桌面任务观察单独通过ExternalObserver接入；不把Claude历史文件变化等同于Codex权威完成通知。

保留现有Codex外部回复镜像。Claude首期必须完成「AA建群、在群恢复原Claude会话、群内运行回复」，不承诺未验证的原生终端实时直播。后续Claude外部观察只新增observer能力，不重写群路由。

名称同步按SessionRef路由给对应工具，保留现有冲突与水位控制，避免因同步改名造成循环或重复建群。Claude正式名称修改仅通过经过验证的官方能力或受测试的适配器实现。

Codex归档复用原生能力。Claude若无等价原生归档API，明确采用桥接归档并保留历史；不能用删除transcript代替归档。工作群完成的现有产品语义本次保持兼容，不引入FF退出指令。

## 默认和迁移

- 当前配置默认工具继续是Codex；已绑定Codex群继续使用同一个原生会话。
- 主动创建的新群保存自己的工具；两工具的默认模型和凭据分别配置，避免传入不兼容模型ID。
- 不迁移或自动复制两工具的会话内容，不提供创建后切换工具。
- 本次不调整个人工作群权限、消息触发策略，不上线同事群、受限环境、项目知识关联或FF生命周期。
- Claude会话在飞书面板和Claude原生历史中管理，不伪装成Codex Desktop原生thread。

## 实施顺序

1. 统一SessionRef/元数据、工具注册表和旧绑定迁移，建立两工具可用状态。
2. 创建表单增加工具选择，设置保存到当前会话，接通按会话执行与工具相关命令/面板。
3. 抽取通用AA同步，接入Claude正式名称发现、原会话恢复及每工具归档。
4. 保留Codex观察器及现有队列行为，检查跨工具去重/锁/名称同步，完成测试、构建和代码交付。

## 验收

- 默认创建使用Codex，选择Claude创建的群所有请求均进入Claude；另一个Codex群不受影响。
- 不允许已创建会话在运行中换工具；旧按钮与无工具字段的命令有明确默认行为。
- Codex与Claude各自AA会话能建群并恢复原ID和cwd；普通命名、子代理或只有preview以AA开头的会话不建群。
- 同名、同UUID、不同来源、同版本族的两工具会话不互相去重、升级、归档或改名。
- 扫描/重启重复事件不重复建群；主动创建AA会话不被二次导入。
- 一个工具不可用或扫描失败时另一个仍可工作；认证和恢复失败不自动切换工具或新建替代会话。
- Codex已有queue、外部回复、原生归档和名称同步检查继续通过；Claude群内流式回复、恢复、取消、历史保留通过。
- 类型检查、相关单元与集成测试、构建及迁移检查通过后交付；部署仍单独按用户授权执行。
